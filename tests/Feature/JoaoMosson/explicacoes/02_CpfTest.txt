O QUE ESTE TESTE VERIFICA
------------------------------------------------------------------------------
* Testa se um CPF válido é aceito, com e sem pontos e traço.
* Testa se um CPF com 9 ou 12 dígitos é rejeitado.
* Testa se CPFs com todos os dígitos iguais (000..., 111..., 999...) são rejeitados com a mensagem "O campo :attribute não é um CPF válido."
* Testa se um CPF com o último dígito errado (...26 em vez de ...25) é rejeitado.

EXPLICAÇÃO:
    MÉTODO AUXILIAR: não começa com "test_", então o PHPUnit NÃO o executa como teste.

CÓDIGO:
            $erro = null;
EXPLICAÇÃO:
    Começa em null, que significa "nenhum erro". Só vira texto se a regra reclamar.

CÓDIGO:
            $this->regra->validate('cpf', $valor, function ($mensagem) use (&$erro) {
EXPLICAÇÃO:
    Chama a regra com três argumentos: o nome do campo ('cpf'), o valor a validar e uma função de callback.
    Em produção o Laravel entrega o $fail para a regra. Aqui nós mesmos entregamos uma função nossa
    que apenas ANOTA a mensagem. Se a regra achar o CPF inválido, ela chama $fail('texto') e cai aqui.
    
    "function ($mensagem) use (&$erro)" é uma função anônima (closure).
    Normalmente uma closure recebe uma CÓPIA das variáveis de fora, e alterar a cópia não afeta a original.
    O "&" antes de $erro passa a variável POR REFERÊNCIA: a closure mexe na variável $erro real
    deste método. Sem o "&", $erro continuaria null para sempre e o teste nunca detectaria falhas.

------------------------------------------------------------------------------

CÓDIGO:
                $erro = $mensagem;
            });
EXPLICAÇÃO:
    Guarda a mensagem enviada pela regra.

------------------------------------------------------------------------------

CÓDIGO:
            return $erro;
        }
EXPLICAÇÃO:
    null  = a regra não chamou $fail = CPF VÁLIDO.
    texto = a regra chamou $fail    = CPF INVÁLIDO (e o texto é o motivo).

CÓDIGO:
        public function test_rejeita_cpf_com_digitos_verificadores_incorretos(): void
        {
EXPLICAÇÃO:
    CASO 4: tem 11 dígitos e não é repetido, mas os 2 últimos números (dígitos verificadores) não conferem.

------------------------------------------------------------------------------

CÓDIGO:
            $this->assertNotNull($this->validarCpf('52998224726'));
        }
    }
EXPLICAÇÃO:
    529.982.247-25 é o correto; invertendo para 26
    
    Como a regra confere o CPF (exemplo com 529.982.247-25; os 9 primeiros dígitos são a "base"):
    1º dígito verificador: multiplica os 9 dígitos da base pelos pesos 10,9,8,...,2 e soma:
    5*10 + 2*9 + 9*8 + 9*7 + 8*6 + 2*5 + 2*4 + 4*3 + 7*2 = 295
    (295 * 10) % 11 % 10 = 2   -> o 10º dígito do CPF TEM que ser 2. E é (529.982.247-2x). OK.
    2º dígito verificador: agora usa os 10 primeiros dígitos e pesos 11,10,9,...,2:
    5*11 + 2*10 + 9*9 + 9*8 + 8*7 + 2*6 + 2*5 + 4*4 + 7*3 + 2*2 = 347
    (347 * 10) % 11 % 10 = 5   -> o 11º dígito TEM que ser 5. Em 52998224725 é 5. OK.
    
    Em "52998224726" o último dígito é 6, mas a conta exige 5. A regra detecta a diferença e chama $fail.
    O 1º dígito verificador continua certo, então este caso prova que o 2º também é conferido.
